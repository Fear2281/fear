# Encore / Neon Karaoke

Веб-приложение на **C# / ASP.NET Core 8** по документу Арсения Шохина. **Ровно два модуля:**

1. **Гость:** вход через QR, выбор одного из 12 столиков, каталог, поиск, фильтры, заявки, голосование, очередь.
2. **Диджей:** вход, модерация, управление выступлениями, настройки, QR-карточки, CSV и история.

Новый интерфейс: тёмный фон, неоновые лаймовые и розовые акценты, короткие подписи. В каталоге **60 записей** (по умолчанию 58 доступны: один explicit и один трек длиннее лимита скрыты). Фонограммы и проигрыватель не входят в проект; сайт управляет заявками и временем выступления.

## Скачать и открыть

Скачай ZIP через **Code → Download ZIP** на GitHub и распакуй. Открой терминал в папке `Encore.csproj`:

```sh
dotnet run
```

Открой `http://localhost:5080`. Нужен установленный .NET SDK 8.0.425 или новее; конфигурация теперь разрешает новые major-версии SDK и runtime. Проверки этого комплекта выполнены на SDK 8.0.425. При первом запуске нужен Интернет для восстановления NuGet-пакетов. В Visual Studio открывай `Encore.sln`.

Для стандартной воспроизводимой сборки:

```sh
dotnet restore --locked-mode
dotnet build --no-restore
dotnet run --no-build
```

В Development пароль диджея — `encore-demo`. В Production встроенный пароль не работает; задай собственный `ENCORE_DJ_PASSWORD` через конфигурацию сервера.

## QR и столики

- Кнопка **«QR входа»** показывает общий QR. Камера телефона открывает сайт, а гость выбирает номер из 12 столиков.
- Выбор номера доступен всем гостям, в том числе в Production. Без выбора нельзя отправить заявку. Кнопка номера позволяет сменить столик.
- В пульте есть **индивидуальные QR**, которые сразу подключают нужный столик.
- `ENCORE_PUBLIC_URL` задаёт адрес в QR (например адрес опубликованного сайта без пути). Без переменной используется адрес запроса.
- `localhost` работает только на том же устройстве. Для телефона требуется домен в Интернете или адрес компьютера в общей сети.
- Выбор столика не подтверждает физическое присутствие. Все посетители одного столика разделяют лимит и один голос на чужую заявку.
- После четырёх часов или перезапуска гостевой сеанс надо создать заново. Его идентификатор хранится в HttpOnly cookie.

## Как разместить в Интернете

Подготовлены **Dockerfile, compose.yaml и Caddy с HTTPS**. Пошаговая инструкция: **[deploy/SERVER.md](deploy/SERVER.md)**.

Кратко: нужен VPS, Docker Compose и домен с DNS A-записью на VPS. Клонируй репозиторий, скопируй `.env.example` в `.env`, укажи домен и собственный пароль, затем выполни:

```sh
docker compose up -d --build
```

Данные сохраняются в отдельном Docker volume. QR автоматически используют заданный домен. Не публикуй Development-режим. GitHub Pages не поддерживает сервер ASP.NET Core. Фактическое размещение на VPS и публичный сертификат требуют настройки вашего хостинга; одного push в GitHub недостаточно.

## Правила и данные

- 2 активные заявки на столик по умолчанию; в пульте лимит меняется от 1 до 5.
- Повтор активного трека одного столика запрещён. Гостевые изменения ограничены 10 операциями на IP в минуту, вход диджея — отдельными 10 попытками.
- Сначала одобренные, затем ожидающие заявки; внутри группы больше голосов → выше, при равенстве — раньше созданная.
- Статусы: waiting → approved → playing → completed. Отклонение и пропуск — конечные статусы. Одновременно одно выступление.
- Таймер завершает текущую заявку по длительности; следующую запускает диджей вручную.
- Ожидание рассчитывается по длительностям предшествующих треков и остатку текущего выступления.
- Обновление интерфейса раз в 3 секунды. WebSocket и Redis не используются.
- «Программа» — название настроения. Фильтр доступности — длительность и explicit; автоматического расписания нет.
- `App_Data/state.json` хранит столики, токены, заявки, голоса и настройки. При обновлении прежние восемь столиков дополняются до двенадцати без удаления существующих токенов и данных.
- `App_Data/keys` хранит ключи Data Protection. `ENCORE_DATA_DIR` переопределяет весь каталог данных. Ограничь доступ к этой папке; она не входит в Git.
- Один серверный процесс на JSON-файл. Для масштабирования нужна БД. Автоматических бэкапов нет.
- Reverse proxy доверяется только по `ENCORE_TRUSTED_PROXY`; Compose задаёт IP Caddy. Это необходимо для HTTPS-cookie, проверки Origin и реальных IP-лимитов.

## Проверки и документация

```sh
python scripts/smoke.py
```

Используются отдельный сервер на 5081 и временное хранилище. Проверяются API, выбор столика, модерация, QR, лимиты, перезапуск и миграция 8 → 12 столиков. Python не нужен самому сайту.

`browser_check.py` — дополнительная проверка Chromium; требует `pip install playwright` и Chromium (`playwright install chromium`, если его нет). Она **создаёт заявки** на запущенном Development-сервере 5080: запускай с пустым временным `ENCORE_DATA_DIR`. Снимки сохраняются в `docs/images`.

- `docs/Encore_Пояснительная_записка.docx` — обновлённый Word-документ с двумя модулями и скриншотами.
- `docs/FUTURE_MODULES.md` — идеи следующих модулей, которые ещё не реализованы.
- `Core/TrackCatalog.cs` — все 60 записей каталога; длительности справочные, не связаны с аудиофайлами.
- `Modules/GuestModule.cs`, `Modules/DjModule.cs` — только два функциональных модуля.
- `Core/`, QR-генерация и таймер — общая инфраструктура.
