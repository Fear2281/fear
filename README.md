# Encore — информационная система для караоке и ресторана

Учебный веб-проект на **C# / ASP.NET Core 8** по документу `Shohin_Arseny_full.docx` и теме из `Список тем.xlsx`. Ровно два функциональных модуля:

1. **Гость:** вход по ссылке/QR столика без регистрации, каталог, поиск, жанры, заявки, голосование, очередь и примерное ожидание.
2. **Пульт диджея:** вход по паролю, модерация, запуск/завершение/пропуск выступления, настройки, QR столиков, история и CSV-отчёт.

Общие модели, хранение и таймер — инфраструктура этих двух модулей. Отдельных панелей администратора, оплаты и лояльности нет.

## Быстрый запуск

Нужен **.NET SDK 8.0.425 или более новая patch-версия той же SDK-серии**. Visual Studio 2022 с поддержкой .NET 8 подходит. Python нужен только для дополнительных проверок и пересборки документа.

```sh
cd fear
# При распаковке архива: перейдите в папку, содержащую Encore.csproj.
dotnet restore --locked-mode
dotnet build --no-restore
dotnet run --no-build
```

Откройте `http://localhost:5080` в браузере. Профиль `Properties/launchSettings.json` включает режим Development. Кнопка «Подключить столик» → «Попробовать за столиком № 1» создаёт гостевой сеанс. Во вкладке «Пульт диджея» учебный пароль: **encore-demo**. Он действует только в Development при отсутствии `ENCORE_DJ_PASSWORD`.

На этой облачной машине SDK установлен в `/workspace/.dotnet`:

```sh
export PATH="/workspace/.dotnet:$PATH"
export DOTNET_CLI_HOME=/workspace/.dotnet-home
export NUGET_PACKAGES=/workspace/.nuget/packages
cd /workspace/fear
dotnet run --no-build
```

## Сценарий демонстрации

1. Подключите столик № 1, найдите Frank Sinatra и закажите трек.
2. Откройте пульт и войдите. Нажмите «Одобрить», затем «На сцену».
3. В пульте откройте ссылку другого столика в другом профиле браузера/инкогнито, чтобы сохранить две независимые сессии.
4. Закажите другую композицию. Поддержите чужую заявку голосом.
5. Завершите первое выступление, запустите следующую одобренную заявку.
6. Измените лимит, поставьте приём на паузу, скачайте CSV и QR-карточку.

Ссылки столиков — bearer-доступ: любой, кто получил такую ссылку, может открыть сеанс этого столика. В учебной версии физическое присутствие гостя не проверяется. Все гости одного столика разделяют лимит заявок и один голос на чужую заявку.

## Данные и правила

- 13 демонстрационных записей каталога; по умолчанию доступны 11: explicit скрыт, трек длиннее 360 секунд скрыт. **Аудиофайлов нет**, названия песен используются как метаданные. На сцене отсчитывается время выступления; звук не воспроизводится.
- `App_Data/state.json`: 8 столиков со случайными 128-битными токенами, заявки, голоса и настройки. Запись через временный файл с последующей заменой. В исходники и архив пользовательские данные не входят.
- Гостевой сеанс: 4 часа, HttpOnly cookie, без регистрации и персональных данных. Сессии находятся в памяти; после перезапуска нужно повторно открыть QR/ссылку.
- Статусы: `waiting → approved → playing → completed`. Отклонение и пропуск — конечные статусы. После истечения длительности текущая заявка завершается автоматически; **следующий трек запускает диджей вручную**.
- Одновременно играет только один трек. Повтор активной заявки одного столика запрещён. По умолчанию не более 2 активных заявок на столик.
- В очереди сначала одобренные, затем ожидающие модерации. В каждой группе: больше голосов → выше; при равенстве — раньше созданная заявка.
- Ожидание — оценка по сумме длительностей предыдущих треков и остатка текущего выступления. Оно изменяется после модерации и голосования и не является обещанием времени выхода.
- API обновляется опросом каждые 3 секунды. WebSocket и Redis не используются.
- 10 гостевых операций записи в минуту на IP; вход диджея имеет отдельный лимит 10 попыток в минуту. Превышение — HTTP 429. Автоматической блокировки столика нет.
- «Настроение» — название программы вечера. Фактическая фильтрация доступности: explicit и максимальная длительность; жанр выбирает гость. Автоматического расписания по времени суток нет.

## QR и запуск в сети

QR генерируются QRCoder 1.6.0 в SVG после входа диджея. По умолчанию адрес берётся из запроса. Для сканирования телефоном сервер должен быть доступен этому телефону. `localhost` на телефоне означает сам телефон.

При запуске в локальной сети задайте `ENCORE_PUBLIC_URL`, например фактический адрес компьютера в вашей сети с портом, и слушайте нужный интерфейс:

```sh
# Linux/macOS. Пример без реального адреса или секретов:
export ENCORE_PUBLIC_URL="http://YOUR_LAN_IP:5080"
dotnet run --no-build --urls http://0.0.0.0:5080
```

Для обычного локального запуска переменная не нужна. Не публикуйте демо-режим в Интернете. Для настоящего развёртывания задайте `ASPNETCORE_ENVIRONMENT=Production`, `ENCORE_DJ_PASSWORD` через защищённое хранилище/переменные сервера, HTTPS и `ENCORE_PUBLIC_URL`. В Production кнопка демо отсутствует и встроенный пароль не принимается. Сырой пароль не сохраняется в JSON; сравнение хэшей в постоянное время, а авторизация после входа использует защищённую cookie ASP.NET Core.

Это учебная реализация для одного процесса. Полноценное промышленное развёртывание потребует БД, управления учётными записями, защищённого хранения ключей Data Protection, конфигурации reverse proxy и резервного копирования. Не запускайте несколько процессов на одном JSON-файле. Гостевые сессии и авторизация требуют повторного входа после перезапуска.

## Проверки

```sh
dotnet build --no-restore
python scripts/smoke.py
```

`smoke.py` поднимает отдельный сервер на 5081, использует временные данные, проверяет API и перезапуск; текущий `App_Data` не меняет. Если `dotnet` отсутствует в PATH, задайте `DOTNET` полным путём к исполняемому файлу.

Дополнительная браузерная проверка:

```sh
pip install playwright
# Установленный Chromium или: playwright install chromium
python scripts/browser_check.py
```

Она работает с запущенным Development-сервером на 5080, **создаёт демонстрационные заявки** и сохраняет снимки в `docs/images`. Для её повторного запуска используйте отдельный пустой `ENCORE_DATA_DIR`. Python-пакеты не нужны самому приложению.

## Документация и структура

- `Program.cs` — конфигурация ASP.NET Core, cookie, лимиты и защитные заголовки.
- `Modules/GuestModule.cs` — гостевые HTTP-маршруты.
- `Modules/DjModule.cs` — защищённые маршруты пульта.
- `Core/MusicStore.cs` — общие модели, правила, JSON-хранилище, таймер.
- `wwwroot/` — адаптивный интерфейс без frontend-сборки, сторонних шрифтов и CDN.
- `docs/Encore_Пояснительная_записка.docx` — Word-документ с архитектурой, двумя модулями, схемой данных, интерфейсами и результатами проверок.
- `docs/images/` — реальные снимки интерфейса и схема архитектуры.
- `packages.lock.json` — зафиксированный NuGet-граф зависимостей.

Документ соответствует этой реализации, а не исходному плану из пяти модулей на Node.js. Интеграция музыкальных сервисов, фонограммы, касса, оплата, JWT, PostgreSQL, WebSocket и отдельный администратор не реализованы.
